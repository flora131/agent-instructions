# Subagent/task UI fidelity review

Design-only, performed directly at the user's request on 2026-09-06. No workflow, runtime implementation, source reuse or publication. This review applies Impeccable shape and operate guidance to the existing RFC and text mockups.

## Design brief and critique

- Audience/job: keyboard-first engineers want to recognize what delegated work is doing, inspect it without losing their place, and act on failures/input requests. This is an Operate surface, not a telemetry dashboard.
- Authority: existing Atomic PRODUCT.md, DESIGN.md and `packages/subagents/src/tui/render-result-compact.ts`. Keep resolved theme roles, literal one-cell working glyph, no-color labels and existing chat/graph key semantics. The current session already ran Impeccable context setup earlier; it was not rerun. This is planning-only, so craft-floor/code implementation was not invoked.
- Defect in the previous draft: collapsed rows led with IDs and repeated execution/observation/elapsed/count fields. Expanded examples were numbered tool-event logs with little prompt/response context. Task descriptions, focused agent detail, type grouping and persistent background discoverability were underrepresented.
- Direction: recognizable role/task titles, tree-connected launch groups, quieter activity/counts, one hint per group, a compact shared footer, and richer focused agent/shell detail. Ctrl+O shows real retained prompt/activity/response through normal message/tool rendering, bounded by viewport and retention.
- Preserve: same live task and execution across Intercom yield, independent default launch, explicit result waits, normal owner cancellation/cooperative JS, best-effort crash cleanup, exact output limits, stage-local skills and quiet in-row completion. No permission or engine policy changes.

## What is adopted and what deliberately differs

Adopt description-first recognition, restrained tree hierarchy, current activity, separate focused detail, compact footer discovery, prompt/activity/response disclosure, conditional hints and null-render spacing discipline. Keep Atomic's own working glyph/theme/action names and standard terminal tool renderers.

Do not copy branded styling, special remote/teammate categories absent from the approved Atomic task schema, reference-specific keybindings, elapsed animation on old transcript rows, or task-list live sorting. Do not claim one continuous upstream generator: earlier source review found an iterator-return/restart path. Atomic's same-execution Intercom guarantee and continuous same-anchor row are intentional improvements required by the user. Quiet completion and all-task inspection including terminal/foreground tasks are retained Atomic choices.

## Spec changes and future proof

The revised full mockups keep the original 26 lifecycle frames with clearer composition, plus two focused agent-detail frames and an empty inspector, 29 total. The RFC embeds selected exact frames and defines the task title fallback, collision disambiguation, grouped/focused views, hint density, footer ownership/counts and transcript adapter. The adapter reads existing owner-authorized session message references; it does not copy full prompts/transcripts into the Rust event journal or synthesize unavailable data.

S4/S5 need tests for identical main/workflow projection, duplicate descriptions, name/path truncation, one hint per group, call/result correlation and accurate counts, empty renderer spacing, empty-string results, current-action emphasis distinct from selection, offscreen-anchor footer discovery, terminal controls, bounded prompt/response/transcript access and Unicode/no-color behavior. Runtime verification remains future work. This pass checks design consistency and text layouts only; it does not claim independent approval or live visual parity.
